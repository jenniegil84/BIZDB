## 1. 폴더 구조 — 공개되는 것은 `site/` 뿐

| 경로 | 역할 | 공개 여부 |
|---|---|---|
| `site/` | 신청 페이지(Netlify Publish directory) | **공개** |
| `apps-script/Code.gs` | 신청 접수 서버(구글 시트 기록 + Flow 업무 등록) — 구글 시트의 Apps Script 에 붙여넣어 쓴다 | 비공개 |
| `harness/` | 검증 스크립트 | 비공개 |
| `*.md` | 작업 문서 | 비공개 |

- `site/` 에는 페이지에 필요한 파일만 둔다. 문서·키·신청자 자료를 넣지 않는다.
- **Flow API Key 는 어떤 파일에도 적지 않는다** — Apps Script 「스크립트 속성」에만 둔다.

## 2. 고칠 때 지킬 것

1. 세미나 내용(시간·문구·문의처·로고·동의 문구)은 `site/index.html` 맨 아래 `SEMINAR` 설정만 고친다.
   값이 `null` 이면 화면에 표시하지 않는다 — 확정 안 된 정보를 지어 넣지 않는다.
2. **회차 규칙은 두 곳에 있다** — `site/index.html` 의 `SEMINAR.scheduleRule`·`upcomingCount` 와
   `apps-script/Code.gs` 의 `CONFIG.schedule`·`allowedSessions`. 한쪽만 바꾸면 서버가 신청을 거절한다.
3. 신청 항목을 추가·변경하면 **페이지 폼 · 페이지 `RULES` · Code.gs `validate_`·`HEADERS` · Flow 본문 · 동의 문구의 수집 항목**을 함께 고친다.
4. Code.gs 를 고치면 사용자가 Apps Script 에 **다시 붙여넣고 「배포 관리 → 새 버전」**으로 재배포해야 반영된다. 보고에 반드시 적는다.
5. 버전을 올리면 `index.html` 의 주석·`page-version`·`PAGE_VERSION`, Code.gs 머리말·`doGet` 을 함께 갱신한다.
6. **(2026-11-12 신설 — 실제 실수)** **고객에게 보이는 화면은 세모리포트 *실서비스* 디자인을 따른다** — 흰 바탕 ·
   민트 포인트(`#4fb8a0`, 버튼 `#3abfa3`) · Noto Sans KR · 보고서식 정보표(머리 2px 검정선 + 회색 라벨칸) ·
   녹색 배너(`#f5f9f5`/`#d4ebd4`). 출처: `semo-report-vat`·`semo-report-corptax` 스킬의 디자인 시스템.
   - **사고**: v00.01에서 *사내용* KPI 대시보드(남색 Metronic형 관리자 화면)의 색을 가져다 고객용 랜딩페이지를 만들어
     사용자가 「디자인 너무 별로」라고 지적했다.
   - **규칙**: 디자인 기준을 고를 때 **사내용(대시보드)인지 고객용(실서비스)인지 먼저 구분**하고, 고객용이면 실서비스 토큰만 쓴다.

## 3. 검증(하네스) — 고친 뒤 둘 다 통과해야 보고한다

```
node "세미나 신청/harness/test_apps_script.js"   # 서버: 회차 계산·검증·중복·Flow 실패 시 보존·수식 주입
node "세미나 신청/harness/check_page.js"         # 화면: 실제 브라우저로 내용·검증·제출·모바일
```

- 실제 구글 시트·Flow 로는 보낼 수 없는 환경이다(네트워크 차단). 하네스는 **가짜 응답**으로 검증한다 —
  보고에 그 점을 밝히고, 실제 연결은 설치 후 사용자 화면에서 확인받는다.
