## 1. 단일 원천 — 같은 숫자는 한 함수에서만 나온다

| 숫자 | 유일한 출처 |

| 채널 요약 4표(유입경로별·가입채널별·최종실적별·요금제변경 채널별)와 그 「최다」 판정 | `perfTbl2()` — 최다는 **대분류(채널) 소계** 기준(v08.201) |
| 채널 판정(유입경로) | `IX_inflowResolve()` |
| 채널 판정(최종실적) | `IX_creditChannel()` |

**검사**
- [ ] 새로 만든 계산이 위 함수 중 하나로 대체 가능한가? 가능하면 새로 만들지 않는다.
- [ ] 같은 이름의 값이 두 함수에서 나오지 않는가? (`pmMasterGap` / `pmOrphanRows` 같은 중복이 실제로 있었다)
- [ ] 고친 함수가 **어디서 호출되는지** 셌는가? 정의 한 줄만 나오면 죽은 코드다.
- [ ] **같은 화면 이름이 다른 렌더링 시스템에 중복 구현돼 있지 않은가?** (예: 주간회의가
      `#content`/`weekShell`과 `#ixHost` 내부 탭 2벌 — `goTab`이 실제로 부르는 쪽이 무엇인지 grep으로 먼저 확정한다)

## 2. 카드 = 목록 = 상세

숫자를 보여주는 곳과 그 숫자를 펼쳐 보는 곳은 **같은 함수**를 쓴다.

**검사**
- [ ] 카드 숫자 = 그 카드를 눌러 열리는 목록의 건수
- [ ] 필터를 바꿔 가며 확인 — 한 조건에서만 맞으면 못 잡는다
      (권장: 이번 달 · 전체 기간 · 지난 달 · 검색 걸었을 때)
- [ ] 일부러 다른 모수를 쓴다면 **그 사실을 화면에 적었는가**
      (예: 「명단 대조」는 명단 34곳 전체와 맞춰야 해서 전체 기간 기준)

## 3. 화면 사이의 필수 등식

### 3-1. 통합 현황

```
누적 가입 − 누적 해지 − 누적 정지 = 현재 정상
```
- 네 값 모두 `perfStat('1900-01-01', 기준일)`에서 나와야 한다.
- 요금제별 현황 합계 = 현재 정상 수

### 3-2. 실적 분석 — 채널 표

```
가입채널별 표 모수  = 신규가입 + 재가입            (마스터)
최종실적별 표 모수  = 신규가입 + 재가입            (마스터)
요금제변경 채널별   = 요금제변경 − 실적 아닌 것    (마스터)
유입경로별 표 모수  = 그 기간 도입 문의            (플로우)
```
- 표에 보이는 건수는 **채널이 지정된 것만**이므로 모수보다 작을 수 있다. 그건 정상이다.
- 다만 **모수 자체**는 위 식과 같아야 한다.
- **네 표의 「최다」는 전부 대분류(채널) 소계 기준**이어야 한다(v08.201) — 소분류 최다가
  섞여 있으면 결론 줄과 아래 표(대분류 소계 순)의 1위가 서로 달라 보일 수 있다.

### 3-2-1. 발생 건 목록(일별·월별·누적·주간회의)의 채널 표시

```
발생 건 목록의 채널 칸 = 최종실적별 실적 표가 그 건에 매긴 값 (IX_creditChannel)
```
- **유입경로(원본)가 아니다.** 실적 관리에서 지정한 값이 최종실적별 표에는 반영되는데
  발생 건 목록에는 옛 유입경로가 남아 있으면 어긋난 것이다(v08.199 사고 재발).
- **예외**: 「유입경로별 실적」 표 자체는 여전히 원본 유입경로를 쓴다 — 그건 다른 질문
  (「어디서 유입됐나」)에 답하는 표다. 이 등식은 발생 건 목록(사건 나열)에만 적용한다.

### 3-3. 실적 관리

```
문의 있는 건 + 문의 없는 실적 = 그 기간 실적 사건 전부
```
- 두 목록이 **겹치지 않아야** 한다. 겹침 판정은 **사업자번호 + 사건 종류**로 한다.
  (업체 단위로만 빼면 「가입 문의만 있는 업체의 요금제 변경」이 어디에도 안 나온다 — v08.191 사고)
- 「문의 없는 실적」과 실적 분석은 **같은 제외 규칙**을 쓴다.

### 3-4. 플러스

```
플러스 가입 + 플러스 전환 = 그 기간 확보한 플러스 (겹침 없음)
월 목표 대상 = (신규가입 ∪ 플러스전환) 중복 제거
```
- 플러스 가입은 **가입 시점 요금제**로 판정한다. 현재 요금제로 판정하면 가입 후 올린 곳이
  양쪽에 잡혀 한 곳을 두 번 센다.
- **주간회의 ①의 플러스 가입 + 플러스 전환도 같은 등식을 따른다**(v08.202·v08.203) — 요금제
  변경 합계에서 전환분을 빼지 않으므로, 이 등식은 "겹침 없이 더한 값"이 아니라 "플러스 확보
  경로별 내역"으로 읽는다(플러스 가입이 신규가입 소계에 이미 포함돼 있는 것과 같은 방식).

## 5. 매칭

**검사**
- [ ] 짝짓기를 **사업자번호로만** 했는가? 사무소명은 축약·띄어쓰기로 잘못 붙는다.
- [ ] 하이픈·공백 차이를 무시하는가? (`String(v).replace(/[^0-9]/g,'')`)
- [ ] 저장 키가 읽는 쪽과 같은 규칙인가?
      「문의 없는 실적」 지정값은 **`M|사업자번호|구분|일자`** 여야 실적 분석이 읽는다.
      「플러스 전환」은 화면 표시용 이름이고 사건은 `요금제변경`이므로 키도 요금제변경이다
      (실적 관리의 문의 없는 실적뿐 아니라 **주간회의 플러스 전환도 같은 원칙** — 사건은
      요금제변경으로 집계되고 화면 이름만 다르다).

## 7. 실적으로 세지 않는 것 (제외 규칙)

세는 화면과 목록 화면이 **같은 규칙**을 써야 한다.

| 제외 | 이유 | 8월 / 전 기간 |
|---|---|---|
| 요금제 변경 전 = 후 | 시스템 재등록 | 5건 / 97건 |
| 구간요금제 → 베이직 | 폐지에 따른 내부 일괄 전환 | 0건 / 48건 |

- **적용**: 실적 분석 채널 표 · 「문의 없는 실적」 목록
- **미적용**: 신청 관리 「고객 현황」 — 「무슨 일이 있었나」를 그대로 보는 화면이라 전건을 보여준다.
  **이건 의도된 차이다**(8월 27건 vs 22건). 정합 오류로 보지 말 것.
