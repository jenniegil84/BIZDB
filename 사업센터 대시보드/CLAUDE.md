11. **(2026-09-03 확정) 모든 데이터값은 없으면 없는대로 표시한다 — 데이터는 하드코딩하지 않는다.**

    화면을 새로 만들거나 고칠 때마다 이 원칙을 기본값으로 적용한다(PROJECT_CONTEXT.md "13. 배운 점" 24·25번 항목 참고).

18. **(2026-09-23 신설 — 같은 실수 2회 반복)** **문서 갱신과 커밋을 한 줄로 이어 붙이지 않는다.** 문서 스크립트가 예외로 멈춰도 뒤따르는 `git commit`이 그대로 실행돼 **코드만 커밋되고 문서가 빠지는** 일이 2026-09-20·09-23 두 번 있었다. **문서 갱신이 성공한 것을 확인한 뒤에 커밋한다**(스크립트 끝에서 바뀐 파일을 확인하거나, 커밋을 별도 명령으로 분리한다).

17. **(2026-09-16, 사용자 지시 "요구는 지키되 더나은 방법이 있다면 제안해")** — **저장소 루트 `CLAUDE.md` 5번 섹션**이 이 원칙을 이미 담고 있어(요청 방식 / 대안 / 차이 / 추천 / 이유) 여기서는 **다시 쓰지 않는다.** 사용자 확인: "중복이라면 생략해도돼". 요청은 그대로 해 놓고, 더 나은 방법은 보고 끝에 짧게 한 번만 덧붙인다.

16. **(2026-09-16 신설, 사용자 지시 — 실제 사고)** **「배포해」는 그때 그 요청 묶음에만 유효하다. 상시 승인으로 해석하지 않는다.**
    - **사고**: 사용자가 앞서 말한 "명령이 모두 수행되면 배포해줘"를 내가 **이번 세션 전체에 걸친 승인**으로 넓혀 잡고, v08.337·v08.338을 **묻지 않고 `main`에 병합·배포**했다. 사용자 지적 — "내가 배포하라고 안했는데 왜 자동 배포했어?"
    - **규칙**: 작업이 끝나면 **작업 브랜치에만 커밋하고 멈춘다.** 그 요청에 대해 사용자가 직접 "배포해"라고 말한 경우에만 `main`에 병합한다.
    - "수행되면 배포해줘"처럼 **조건을 단 말도 그 묶음 한 번**에만 적용한다. 다음 요청에는 다시 확인받는다.
    - 되돌리는 것(revert)도 배포다 — 마찬가지로 먼저 확인받는다.
    - 사용자가 배포를 원할 것 같아도 **내가 대신 판단하지 않는다**(16번 섹션의 대원칙).

15. **(2026-09-16 신설 — 실수 재발 방지, PROJECT_CONTEXT.md v03.17)** **빈 값을 이어 붙인 문자열은 「값 없음」이 아니다.** `a+'|'+b` 같은 합성 키는 둘 다 비어도 `'|'`가 되어 **참**이다 — 「없으면 판단하지 않는다」 가드를 그 합성 값으로 세우면 영원히 걸리지 않는다(실제 사고: 새 버전 알림 띠가 헤더 없는 서버에서 구조적으로 안 뜸, v08.328에서 수정). **조각을 각각 검사한 뒤 합친다.**
